## Scope decisions worth flagging explicitly

**The Phase 02 shell (`src/shell/router.js` placeholders) was deliberately left untouched.** The roadmap's Phase 03 task list is "Define contracts, implement normalized state + selectors, create fixture provider" — it does not say "wire fixtures into the shell UI". Touching `src/shell/**` would mean modifying a file another phase (02) owns, and displaying `Pattern`/`RelationshipSignal` fixture data in the running app risked reading as "new visual intelligence" even though the underlying data is static. Instead, the Definition of Done ("new UI can consume fixture contracts without touching engine internals") is proven by the test suite: `tests/state.test.js` loads every fixture through the exact same `store.js` + `fixture-provider.js` path a future UI would use, asserts the result is fully populated and contract-valid, and statically asserts `fixture-provider.js` never imports `engine.js`. Whoever picks up Phase 04 can wire the astrology fixture (or by then, real astrology signals) into the `systems/astrology` placeholder as their first concrete step.

## What was built

New files, all additive under `src/core/`:

- `src/core/contracts/enums.js` — shared vocabulary: `SYSTEMS`, `DOMAINS` (Living Self Model's 8 core dimensions), `CONFIDENCE_LEVELS`, `CALCULATION_STATUSES`, `PATTERN_TYPES` (the 8 types from Design Spec §4's table, verbatim labels), `RELATIONSHIP_DIMENSIONS` (extrapolated, see above), `EDGE_TYPES` (Personal Knowledge Graph edge vocabulary, §3 — not yet consumed by any contract field, provided for a future phase that models the graph shape directly), plus small `assertOneOf`/`assertString`/`assertArray`/`assertNumber` validation helpers shared by every contract.
- `src/core/contracts/calculation-metadata.js` — the "calculation status and engine version metadata" shape from the task list; enforces that `approximate`/`unavailable` statuses always carry a human-readable `note` (Design Spec §19: "no silent approximation").
- `src/core/contracts/system-signal.js`, `evidence.js`, `pattern.js`, `timeline-event.js`, `relationship-signal.js` — one factory function per contract (`createX(data)`), each validating required fields/enums/ranges and returning a frozen object. Malformed input throws with a field-specific message rather than failing silently.
- `src/core/contracts/index.js` — barrel export.
- `src/core/state/store.js` — normalized state container (`signals`, `evidenceBySource`, `patterns`, `timelineEvents`, `relationshipSignals`, each keyed by id) with `loadX()`/`getState()`/`subscribe()`/`reset()`. Every `loadX()` runs the matching contract factory, so bad data is rejected at load time, not silently stored.
- `src/core/state/selectors.js` — pure projections only (by-system, by-domain, by-id, evidence-for-source, pattern→signals resolution, timeline range filter, relationship pair lookup order-independent, calculation-status tally). No selector combines systems into a new claim.
- `src/core/state/fixture-provider.js` — static fixture data for all five systems (5 signals for a primary fixture person, one per system) plus a small second fixture person (2 signals) used only to exercise `RelationshipSignal`; evidence fixtures covering all three calculation statuses (including a deliberately illustrative `unavailable` example); one illustrative `Pattern`; one illustrative `RelationshipSignal`; plus `loadAllFixturesIntoStore(store)` as the one-call demonstration of the Definition of Done.
- `src/core/state/index.js` — barrel export.
- `tests/contracts.test.js` — 14 tests covering acceptance and rejection paths for every contract and the enum set.
- `tests/state.test.js` — 12 tests covering the store, selectors, and fixture provider, including the static "never imports engine.js" check.

No existing file was modified in this phase.
